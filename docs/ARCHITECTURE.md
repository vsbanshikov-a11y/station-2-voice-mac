# Как это устроено

```text
Фраза владельца
  → Станция: обработанный звук микрофона
  → защищённое SSH-соединение → Mac: локальное распознавание фразы
  → после «Переходим в ворк»: отдельный голосовой сеанс Codex
  → при необходимости: доступные инструменты Codex на Mac
  → ответ голосом → Mac → SSH → динамик Станции
```

Обычный чат остаётся активным. Во время рабочего режима дополнительный канал подаёт в него тишину; после возврата или прекращения продления переключения исходный чат снова получает звук. Сторожевой процесс пытается восстановить исходный локальный сокет Станции при аварийном завершении дополнительного канала. Это не гарантия восстановления при каждом возможном сбое питания или системы.

На Mac дополнительный браузерный процесс и локальный сервер обеспечивают WebRTC. Сервер слушает только loopback и использует случайный токен для доступа. Постоянные записи речевых фрагментов и текст распознавания проектом не сохраняются. Временный речевой фрагмент для локального распознавателя передаётся через временный файл, который автоматически закрывается и удаляется.

Codex и обычный голосовой чат — разные сеансы. В этом выпуске рабочий сеанс временный и не объединён с историей закреплённого чата. Управление приложениями зависит от разрешений, а запросы специального подтверждения пока отклоняются.

Компоненты: `voice_service.py` следит за состоянием обычного чата; `frame_dispatcher.py`, `speech_segments.py` и `recognizer.py` обнаруживают фразу; `mode_router.py` координирует переходы; `relay/` обеспечивает аудиоканал и откат; `work_session.py`, `work_page.html` и `pcm_bridge.py` подключают голосовой сеанс.
