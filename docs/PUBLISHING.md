# Как опубликовать проект на GitHub

GitHub — сайт, на котором хранится версия проекта и история изменений. На компьютере находится **локальный репозиторий**, а на GitHub после публикации появится его **удалённая копия**. Пока репозиторий не опубликован, другие люди его не видят.

`README.md` — главная страница проекта. Она открывается посетителю сразу. Инструкции в папке `docs` помогают человеку установить и использовать программу. Кнопка **Issues** на странице проекта позволяет пользователям сообщать об ошибках, если автор включил эту функцию.

## Перед публикацией

1. Прочитайте [README](../README.md) и [инструкцию установки](INSTALL.md): в них должно быть понятно, что именно проверено и что пока не поддерживается. В частности, этот проект пока не устанавливает root и не даёт готового проверенного пути установки колонки с нуля только на Mac.
2. Проверьте список файлов. Не должны попадать SSH-ключи, `known_hosts`, данные входа, cookie, токены, пароли, персональные адреса устройств, логи с личной информацией, аудиозаписи разговоров, данные календаря, модель `models/` и собранный бинарник `relay/station-relay`. Файл `.gitignore` помогает не добавить некоторые из них, но не заменяет ручную проверку.
3. Не добавляйте не принадлежащую вам прошивку, файлы исходного голосового клиента или чужой код без понимания разрешений. Здесь исходный клиент указан отдельной зависимостью.
4. Для собственного кода проекта подготовлена лицензия [MIT](../LICENSE). Она не заменяет лицензии исходного клиента и других зависимостей. Системные голоса Apple и созданные ими аудиофайлы не распространяются как часть этого репозитория; подтверждение создаётся локально. Изучите [справку GitHub о лицензиях](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository) и условия зависимостей.
5. Начните с **приватного** репозитория, если хотите спокойно проверить файлы и оформление. Приватный и публичный варианты выбираются в окне публикации; публичную копию смогут увидеть все.

Если секрет случайно попал в опубликованную историю, простого удаления файла из последнего коммита недостаточно: секрет нужно отозвать или заменить и отдельно очистить историю. См. [справку GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

## Публикация через GitHub Desktop

Понадобятся аккаунт GitHub и установленный [GitHub Desktop](https://desktop.github.com/). Войдите в аккаунт в самом приложении.

1. В GitHub Desktop откройте **File → Add Local Repository**.
2. Нажмите **Choose**, выберите папку локального проекта, где находятся `README.md` и скрытая папка `.git`, затем нажмите **Add Repository**. Если программа сообщает, что папка не является репозиторием, её сначала нужно инициализировать в Git или создать репозиторий через GitHub Desktop; не выбирайте папку со своими ключами вместо папки проекта.
3. Посмотрите список изменений. В поле **Summary** напишите, например, `Первый выпуск`, и нажмите **Commit to main**. Коммит пока сохраняется только на вашем Mac.
4. Нажмите **Publish repository**. Выберите название и описание. Оставьте **Keep this code private**, чтобы сначала проверить приватную версию, или снимите отметку для публичной публикации. Убедитесь, что выбрана нужная учётная запись, и нажмите **Publish Repository**.
5. Откройте **Repository → View on GitHub**. Проверьте, что видны главная страница, `docs/INSTALL.md` и исходники, а личных файлов нет. Попросите другого человека пройти установку с отдельного устройства: текущая инструкция ещё не проверена на независимой чистой установке.

Официальные справки: [добавление локального репозитория](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-a-repository-from-your-local-computer-to-github-desktop), [публикация](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-an-existing-project-to-github-using-github-desktop).

## Как обновлять проект

После изменений проверьте их, внесите понятное описание в **Summary**, сделайте коммит и нажмите **Push origin**. Посетители увидят новую версию после отправки. Не обещайте поддержку другой модели, другого тарифа или установки с нуля, пока они не проверены.

Для первого публичного выпуска полезно добавить историю изменений, фотографии или короткое видео с замазанными личными данными, список проверенных устройств и FAQ. Не публикуйте реальные разговоры без согласия участников.
